# Contributing to ESP32 Central

Thanks for your interest in improving **ESP32 Central**. This project is presented as a polished embedded portfolio piece, so contributions that improve clarity, reliability, documentation, and maintainability are especially welcome.

## How you can contribute

You can help by:

- Improving documentation and examples
- Refining the README, screenshots, and demo assets
- Reporting bugs or suggesting enhancements
- Improving code structure, naming, or maintainability
- Adding compatibility notes for hardware or libraries

## Before you submit

Please make sure your contribution:

- Is focused and easy to review
- Uses clear commit messages
- Does not introduce secrets, credentials, or private network details
- Preserves the project’s local-network security assumptions
- Includes screenshots or notes if it changes visible behavior

## Suggested workflow

1. Fork the repository.
2. Create a feature branch.
3. Make your changes.
4. Test or verify the result where possible.
5. Open a pull request with a clear summary of what changed.

## Pull request guidelines

A good pull request should include:

- A short description of the goal
- What was changed
- Why the change matters
- Any screenshots or demo links, if relevant
- Any compatibility or setup notes

## Documentation-first contributions

If you are contributing to the portfolio presentation, consider improving:

- `README.md`
- `CHANGELOG.md`
- `docs/screenshots/`
- `docs/demo/`

## Code style

When editing firmware or helper modules:

- Keep the code readable and modular
- Prefer descriptive names
- Avoid unrelated refactors in the same pull request
- Keep changes aligned with the existing architecture

## Need help?

If you are unsure where to start, open an issue or describe the improvement in the pull request discussion.

---

Thank you for helping make **ESP32 Central** better.
